Section 2

Authentication And Routing Flow

The project supports both Supabase-backed admin auth and a local fallback admin password mode. Routing is unified through `routes.js`, and protected pages gate access through `lbAuth.requireAuth()`.

index.html admin-login.html assets/js/routes.js assets/js/auth.js netlify.toml _redirects login/index.html records/index.html
Section 3

Lingkod Bayan Client Records Runtime

`client-records.html` is the operational hub of the app. It initializes the shared record store, renders the main table, exposes the detail/history workspace, and links outward to add-record, reports, imports, and CEU.

client-records.html assets/js/data-store.js assets/js/record-attachments.js assets/js/ceu-referrals.js assets/js/routes.js assets/js/auth.js
Section 4

Add Record And History Save Flow

`add-record.html` can either create a brand-new client record or append a new request/history entry to an existing client, depending on name matching and duplicate-request checks.

add-record.html assets/js/data-store.js assets/js/record-attachments.js assets/js/ceu-referrals.js assets/js/barangays.js assets/js/puroks.js
Section 5

Client Assistance Summary Report Flow

The report page is a read/compute/print workspace: it reads the shared client records, filters them, computes breakdowns and graphs, and prepares filtered print/export outputs.

reports.html assets/js/data-store.js assets/js/barangays.js assets/js/puroks.js
Section 6

CEU Database And Referral Summary Flow

The CEU page is its own protected workspace backed by the `ceu_records` table. It also contains the inline referral summary, which cross-matches active CEU names against Lingkod Bayan client referral values.

ceu-database.html assets/js/ceu-referrals.js assets/js/data-store.js assets/js/supabase-config.js assets/js/supabase-client.js
Section 7

Import Tools, Backup Migration, And Excel Import Flow

The admin tools page handles two different import tracks: one-time migration of preserved browser data into Supabase, and workbook-based import that merges repeat requests into client history.

import-tools.html assets/js/import-tools-page.js assets/js/record-excel-import.js assets/js/xlsx-lite.js assets/js/data-store.js
Section 8

Supporting Files, SQL Setup, And Non-Live Runtime Areas

These files matter to the complete system map, but they are not the day-to-day interactive runtime pages in the same way as `client-records.html` or `ceu-database.html`.

Supabase setup and seed files

`supabase/setup.sql` creates the main shared tables, allow-list, audit log, and policies. `supabase/ceu-seed.sql` plus `supabase/ceu-seed-parts/*` populate CEU data. `supabase/lbu-client-import-setup.sql` plus `supabase/lbu-client-import-parts/*` are import-oriented SQL assets for Lingkod Bayan records.

supabase/setup.sql supabase/ceu-seed.sql supabase/lbu-client-import-setup.sql

Edge / cleanup support

`supabase/functions/cleanup-record-attachments/index.ts` is support infrastructure around attachment lifecycle. It is part of the broader system picture even though the live HTML pages do not execute it directly in the browser.

cleanup-record-attachments/index.ts assets/js/record-attachments.js

Clean-route wrapper folders

Folders like `/records`, `/login`, `/add-record`, `/reports`, `/import-tools`, and `/ceu-database` contain tiny `index.html` wrappers that redirect to the root HTML pages. They support clean browsing and deployment behavior.

records/index.html login/index.html add-record/index.html reports/index.html

Standalone local form

`local-form.html` is intentionally separate from the authenticated admin runtime. It keeps answers in-browser and offers JSON download, but it does not submit into the main app database by default.

local-form.html

Scripts and workbook helpers

The `scripts/` folder contains helper scripts such as CEU data generation tooling. These are operational/project-maintenance assets, not end-user browser pages, but they still support the broader data pipeline.

scripts/

Archive and reference-only material

`archive/` and workbook inspection/reference folders are useful historical context, but they are not treated as live runtime pages in this flowchart.

archive/ data/
